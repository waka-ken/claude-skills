# ギャップ監視 — docs テキストレビュー仕様

人がタスクを書いて AI に依頼する既存パイプライン（`notion-claude-pipeline-spec.md`）の**逆方向**:  
AI（GAS）がリポジトリの **ドキュメント群** を読み、改善・仕様・余剰の提案タスクを Notion に積み続ける。

> 状態: **docs テキストのみ**前提で再設計（`gap_monitor.gs`）。  
> 関連: `[DB]オールタスク管理` / `gap_monitor.gs`

---

## 0. 大前提（必読）

| する | しない |
|------|--------|
| `README` / `docs/**` / ADR の**テキスト**を読む | ソースコードを読まない |
| Gemini で改善・仕様・余剰を判断 | GitHub Issue / PR と比較しない |
| Notion に**提案タスクのみ**作成 | GitHub Actions に処理を広げない |
| GAS 一本で統合運用 | リポへの書き込み・Issue 操作をしない |

Issue を課題管理に使わない運用のため、Issue/PR 突合は廃止した。  
コード全読解や Actions 展開も、現時点の意図外。

---

## 1. 目的

ドキュメントに書かれているプロジェクト像から:

1. **よりよい改善箇所**
2. **仕様としてあるべき（欠け・曖昧）**
3. **余剰（重複・陳腐化・過剰）**

を判断し、人がレビューできる形で Notion タスク化する。

出口は従来どおり: 人が見てから必要なら `AIステータス = AIに依頼`。

---

## 2. 暴走防止

1. 判断材料は **docs テキストのみ**
2. GAS の書き込みは Notion（＋任意 Slack）のみ。GitHub は **読み取りのみ**
3. タイトル Prefix で種別を明示。本文は理想 / 現状 / 乖離
4. 細かい手順書の書き直し・見出し整理だけの提案は出さない（プロンプトで抑制）

リポジトリ側に制御ファイルは置かない（workflow も不要）。

---

## 3. 提案種別（Prefix）

| Prefix | kind | 意味 |
|--------|------|------|
| `[ギャップ/改善]` | `improve` | 文書から見える価値ある改善点 |
| `[ギャップ/仕様]` | `spec` | あるべきなのに無い／曖昧な仕様 |
| `[ギャップ/余剰]` | `surplus` | 重複・古くて不要そうな記述 |

---

## 4. 運用枠

| 項目 | 値 |
|------|-----|
| 実行基盤 | **GAS 一本**（時間トリガー） |
| LLM | 既存 `GEMINI_API_KEY`（`gemini-2.5-flash`） |
| 最初の対象リポ | `waka-ken/core-RAG`（※リポ≠単一プロジェクト。タスクは内容でプロジェクト振分） |
| 頻度 | 毎日（例: 朝 9:00） |
| 上限 | **最大 10 件/日** |
| docs 対象 | `README.md` + `docs/**` + ADR 系 |
| 作成順 | 優先度 高 → 中 → 低 |

---

## 5. 処理フロー

```
[GAS 時間トリガー]
  │  対象リポ（初期: core-RAG）
  ▼
[GitHub API 読み取り]
  │  README / docs / ADR のテキスト取得
  ▼
[Gemini]
  │  改善 / 仕様 / 余剰 + 適切な Notion プロジェクト
  ▼
[fingerprint 照合（Notion）]
  │  却下 / 保留(30日) / 既存追跡中はスキップ
  ▼
[Notion タスク作成]
  │  Prefix・本文・Fingerprint・プロジェクト relation・コメント
  │  （任意）Slack
  ▼
[人]
     採用 → AIに依頼 / 保留 / 却下
```

プロジェクト振分は `[DB]プロジェクト管理` の未完了一覧を毎回取得する。  
**リポの GitHub 欄一致では決めない**（core-RAG のように共有基盤だと Jackson に偏るため）。

優先順:
1. 根拠パス・タイトル・本文にクライアント／プロジェクト名が出ている  
2. Gemini の `project_name`（高信頼かつ共有リポバイアスでない）  
3. デフォルト（Jackson office project）

---

## 6. fingerprint

形式: `gap/{kind}/{repo}/{key}`  
`key` は Gemini が返す安定キー（英数字・ハイフン）。

| 条件 | 動作 |
|------|------|
| `タグ=却下` | 永続スキップ |
| `タグ=保留` かつ `last_edited_time` が 30 日以内 | スキップ |
| 未着手 / 進行中 / 完了 など既存 | スキップ |

`Dispatch ID` とは別プロパティ `Fingerprint`。

---

## 7. Notion

既存オールタスク DB に混在。

| 流用 | 使い方 |
|------|--------|
| `GitHubリポジトリ` | 対象リポ |
| `プロジェクト` | **提案内容から Gemini が選択**（リポ名からの固定紐付けではない） |
| `優先度` | Gemini 付与 |
| `タグ` | 人の進捗（初期 `未着手`。`保留`/`却下` 推奨） |
| `AIステータス` | 採用して依頼するまで空 |
| 本文 | 理想 / 現状 / 乖離 |

新規: `Fingerprint`（済）

---

## 8. 本文テンプレ

```markdown
## 理想
…

## 現状
…（文書上の記述に基づく）

## 乖離
程度: 大 / 中 / 小
内容: …
```

由来・fingerprint は作成時コメントへ。

---

## 9. 既存パイプラインとの境界

| | ギャップ監視（本仕様） | AI 依頼パイプライン |
|--|------------------------|---------------------|
| 入力 | docs テキスト | 人が書いたタスク |
| 実行 | GAS + Gemini | GAS Dispatch → Actions |
| GitHub 書き込み | なし | あり（PR 等） |
| キー | `Fingerprint` | `Dispatch ID` |

---

## 10. セットアップ

1. `Fingerprint` プロパティ（済）
2. （推奨）`タグ` に `保留` / `却下`
3. スクリプトプロパティ: `NOTION_TOKEN` / `GITHUB_PAT` / `GEMINI_API_KEY`（`SLACK_TOKEN` 任意）  
   - docs 読み取りには Classic PAT の `repo` 等、Contents 読取ができれば足りる
4. `setupGapMonitorTrigger()` → `testGapMonitor()`

---

## 11. 決定ログ

- 大前提: **docs/README/ADR テキストのみ**（コード・Issue・Actions なし）
- 出口: Notion 提案のみ
- 種別: 改善 / 仕様 / 余剰
- 上限 10・GAS 完結・Gemini・core-RAG から
- **リポ≠単一プロジェクト**: 内容を見て Notion プロジェクトを振分（メール取り込みと同じ解決ロジック）
- Issue 突合・見出し機械突合は廃止（ノイズのため）
